# 多语言

界面文字在 `ui/locales` 的 ARB 目录里，直接编辑。它们最初由原版前端的 i18next 语言包（`wails-final` 标签的 `apps/desktop/frontend/src/locales/<语言>.json`）转换而来，key 沿用原版。支持的语言与原版相同：简体中文 `zh-CN`（源语言，也是回退语言）、繁体中文 `zh-TW`、英语 `en-US`、日语 `ja-JP`，显示哪种由配置的 `language` 决定。

## 结构

| 路径 | 内容 |
| --- | --- |
| `ui/locales/<语言>.json` | MyGo 的 ARB 目录，**直接编辑**。消息名是原版的 key 拍平：点号换成 `_`（`common.confirm` → `common_confirm`）；源语言 `zh-CN.json` 的每条消息带 `@<消息名>` 的 `description`，写原版的 key（原版没有的写 `extra:native.<名字>`）。参数是 ICU 的 `{name}`，文字里的 `{`、`}`、`'` 按 ICU 的规则转义 |
| `native_*` 消息 | 原版没有的文字：原版硬编码的中文、原生界面才有的无障碍标签、占位页 |
| `ja-JP.json` 里的 `mygo.*` | MyGo 自带文字的日语翻译（MyGo 没有日语，键见 MyGo 的 `internal/l10n/en.json`） |
| `ui/locales/catalog_gen.go` | `mygo generate` 写出的类型化函数，每个消息一个，注释里是消息与原版的 key；**不要手改** |
| `ui/locales/renames.go` | 两个 key 拍平后重名时（`idPreviewLoading` 与 `idPreview.loading`），其中一个在 ARB 里的新名字，`locales.Key` 按它查找 |
| `ui/locales/key.go` | `locales.Key("原版.key", 参数...)`：按原版的 key 动态取消息 |
| `ui/tagname/data/<语言>.json` | VNDB 标签译名（最初复制自原版的 `utils/vndbTagTranslations.<语言>.json`），直接编辑 |

## 改了语言包之后

```sh
pnpm i18n                         # 在仓库根目录；即在 apps/desktop 下 go run ./tools/mygo generate
```

`mygo generate` 检查四种语言的目录（参数、ICU 语法）并重新写出 `catalog_gen.go`。新消息四种语言都要写；加到源语言 `zh-CN.json` 时同时写上 `@<消息名>` 的 `description`。

## 在界面里说一句话

找原版组件在同一处用的 key，用对应的函数：

```go
// 原版：toast.success(t("library.toast.batchStatusUpdated", { count, status }))
e.Toast(c, env.Success(locales.LibraryToastBatchStatusUpdated(strconv.Itoa(n), locales.CommonPlaying())))
```

- **key 到函数名**：点号换成 `_`，再按 `_` 分段、每段首字母大写：`gameEdit.downloadCover` → `GameEditDownloadCover`，`settings.metadata.idPreview.reasons.no_mapping` → `SettingsMetadataIdPreviewReasonsNoMapping`。不确定时在 `catalog_gen.go` 里搜 `// 原版的.key`。
- **参数都是 `string`**，顺序是参数在源语言消息里出现的顺序（见函数签名）。i18next 原样插入值，所以数字由调用方格式化（`strconv.Itoa`、`fmt.Sprintf("%.1f", …)`），这样 Steam AppID 之类的数字不会被加上千分位。
- **原版用变量拼 key**（`` t(`gameEdit.status.${s}`) ``）时用 `locales.Key("gameEdit.status."+s)`；固定的 key 一律用生成的函数，拼错在编译期就能发现。
- **每帧取**：视图每帧重建，直接在构建时调用函数即可（没有参数的消息第二次只是一次 map 查找）。**不要**把翻译结果存进包级变量、常量、结构体字段或 `ui.Local`，否则切换语言后不会更新；需要一张表时存函数（`label func() string`）或 key。
- **元素的 key 不用翻译后的文字**：`c.Key(locales.X())` 会让元素在切换语言时变成另一个元素（丢失动画、悬停、焦点），用稳定的标识（路径、ID、英文常量）。
- **不翻译**：开发者看的文字（命令行参数说明、日志、内部错误前缀）、游戏数据、测试数据。
- **检查**：`ui/locales` 的 `TestNoHardcodedText` 扫描 `ui` 下的非测试代码，出现中文、日文的字符串字面量就失败。确实不该翻译的在同一行写注释 `// i18n:keep：原因`。

### 原版没有的文字

先找原版里意思相同的 key（无障碍标签可以用对应页面的标题，如 `downloads.title`）。确实没有时在四种语言的 ARB 里加一条 `native_<名字>`（`zh-CN.json` 的 `description` 写 `extra:native.<名字>`），再重新生成。原版里硬编码的中文（如 BetterSelect 的“请选择”）也这样处理。

## 日期、时长与数字

- 时长用 `timefmt.Duration`、`timefmt.DurationChart`，单位来自 `common.duration.*`。
- 日期用 `timefmt.Date`、`timefmt.DateTime`、`timefmt.DateTimeMinutes`：MyGo 的 `i18n.FormatDate` 按 CLDR 排列（zh-CN `2026/09/11`、en-US `09/11/2026`），与原版的 `toLocaleDateString`/`toLocaleString` 一致。原版用 WebView 的默认语言，这里用应用的语言加用户在系统里设置的区域格式。
- 其他按语言格式化的地方（原版的 `Intl.DateTimeFormat(i18n.language, …)`、`toLocaleString`）用 `i18n.FormatDate(timefmt.FormatLocale(), …)`、`i18n.FormatNumber(timefmt.FormatLocale(), …)`：应用的语言加区域格式，测试里是 zh-CN。

## 运行时

- 启动时 `env.ApplyLanguage(config.Language)` 调用 `mygo.App.SetLocale`；为空或不支持时跟随系统语言，都不匹配时显示 zh-CN（原版的 `LanguageDetector` + `fallbackLng`）。设置页迁移后，修改语言时同样调用它。
- `-lang en-US` 只在这次运行里显示另一种语言（MyGo 的 `MYGO_LOCALE`），不写进配置。`-lang en-XA` 是伪语言：源语言的文字加上重音、拉长三分之一并用方括号括起来，没有括起来的文字就是漏掉的硬编码，被截断的是给翻译留的空间不够；`-lang ar-XB` 从右到左排版。
- MyGo 自带的文字（输入框右键菜单、文件对话框标题等）：zh-CN、zh-TW 用 MyGo 的 `zh-Hans`、`zh-Hant`，en-US 用 MyGo 的英文；ja-JP 用 `ui/locales/ja-JP.json` 里 `mygo.*` 的翻译（键见 MyGo 的 `internal/l10n/en.json`）。

## 测试

没有运行 App 时（`go test`），生成的函数说源语言 zh-CN，所以测试里可以直接断言中文，或者用 `locales.X()` 断言，文字改了也不用改测试。要在测试里换语言，用 `i18n.SetLocaleFunc(func() string { return "en-US" })`，结束时 `i18n.SetLocaleFunc(nil)`。
